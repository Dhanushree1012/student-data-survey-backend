# Contributing

## Branching

- `main`: protected release branch
- `feature/backend-infrastructure`
- `feature/android-offline`
- `qa/release-validation`
- `docs/project-documentation`

## Commit conventions

- Use descriptive commit messages.
- Keep each feature or restructure scoped to one concern.
- Never commit secrets, credentials, or real student records.

## Review requirements

- Require a pull request before merge to `main`.
- Review logic, migration, and security impact together.
- Ensure tests pass before merging.
